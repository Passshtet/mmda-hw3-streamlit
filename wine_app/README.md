# Вино для подборки

Приложение к ДЗ-3. По лабораторным показателям оценивает вероятность того, что вино получит не меньше 7 баллов, и решает, включать ли его в подборку.

## Запуск

Проверено на Python 3.12.16. Команды из папки проекта:

```bash
cd wine_app
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Приложение откроется по адресу `http://localhost:8501`. Можно запускать и из другой директории: пути к модели и данным строятся от `Path(__file__).resolve().parent`.

## Файлы и вкладки

- `model.joblib` — обученный пайплайн `StandardScaler → LogisticRegression` без весов классов.
- `config.json` — порог, выбранный по максимуму F1 на валидации.
- `test.csv` — отложенная выборка для показа метрик.
- «Одно вино» — 11 числовых признаков и переключатель цвета вина. После ввода нажмите «Рассчитать».
- «Модельные метрики» — матрица ошибок, precision, recall, F1, ROC- и PR-кривые. Красные точки соответствуют текущему порогу.
- «Загрузить CSV» — пакетное предсказание и скачивание результата. Пример файла можно скачать на этой вкладке.
- «Что выучила модель» — коэффициенты при стандартизованных признаках.

Порог в боковой панели общий для всех вкладок. При его увеличении отбор становится строже, при уменьшении — шире. Слайдер нужен для демонстрации: подбирать рабочий порог по показанным тестовым метрикам нельзя.

CSV должен содержать столбцы `fixed_acidity`, `volatile_acidity`, `citric_acid`, `residual_sugar`, `chlorides`, `free_sulfur_dioxide`, `total_sulfur_dioxide`, `density`, `pH`, `sulphates`, `alcohol`, `is_red`. Порядок столбцов не важен, дополнительные столбцы сохраняются в результате. Все признаки должны быть числовыми и заполненными, `is_red` — 0 или 1. В результате добавляются `probability` и `recommend` (1 — включить в подборку).

## Кэширование

`st.cache_resource` сохраняет один объект модели на сервере: повторно читать и копировать его при каждом действии пользователя не нужно. `st.cache_data` подходит для таблиц и массивов: сохраняет результат вычисления и возвращает его копию. Так кэшируются чтение `test.csv` и вероятности на тесте. Аргумент `_model` исключён из хеширования; версия файла модели передаётся отдельно, чтобы при замене модели обновился и кэш вероятностей.

При изменении порога для теста заново выполняется только сравнение вероятностей с порогом и расчёт метрик. Без декоратора `joblib.load` читал бы модель с диска при каждом перезапуске скрипта. В приложении модель не обучается.

Источник: [документация кэширования Streamlit](https://docs.streamlit.io/develop/concepts/architecture/caching).

## Подготовка данных

Модель и порог сохранены из `HW3_MMDA.ipynb`. Из исходных 6497 строк до разбиения удалены 1177 полных повторов. Разбиение стратифицированное, `random_state=42`; масштабирование обучается только на тренировочной части. Порог подбирается на валидационной части train, после чего пайплайн переобучается на всём train. В этой папке уже есть все артефакты, выполнять ноутбук перед запуском приложения не требуется.

## Streamlit Community Cloud

Для публикации нужен аккаунт Streamlit Community Cloud, связанный с GitHub, и репозиторий с этой папкой.

1. Загрузить `wine_app/` в GitHub-репозиторий.
2. На [share.streamlit.io](https://share.streamlit.io/) выбрать **Create app** и указать репозиторий, ветку и путь `wine_app/app.py`.
3. В **Advanced settings** выбрать Python 3.12 и запустить деплой.

Если содержимое папки лежит в корне репозитория, путь к основному файлу — `app.py`. Зависимости берутся из `requirements.txt`, расположенного рядом с приложением. Секреты и дополнительные сервисы не нужны.

Инструкция: [деплой в Community Cloud](https://docs.streamlit.io/deploy/streamlit-community-cloud/deploy-your-app/deploy).
